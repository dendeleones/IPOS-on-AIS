\section{Теоретические модели, методы и алгоритмы исследования}

\subsection{Модель производственной системы и параметры планирования}

В основе задачи лежит модель гибкого производственного участка (Flexible Job Shop) \cite{machinostroy}, состоящая из множества заказов $J = \{J_1, J_2, \dots, J_n\}$ и множества ресурсов $R = \{R_1, R_2, \dots, R_m\}$. Каждый заказ $J_i$ характеризуется директивным сроком $d_i$, приоритетом $w_i \in [0.5, 2.0]$ и содержит ровно одну технологическую операцию $O_i$ (ограничение, принятое в разработанной системе). Операция $O_i$ задаётся следующими параметрами:

\begin{itemize}
    \item тип операции (фрезеровка, сборка, сварка);
    \item нормативная длительность $p_i$ (мин);
    \item количество деталей (целое положительное число).
\end{itemize}

Для каждого ресурса $R_k$ определены:

\begin{itemize}
    \item текущий статус (Работает или Авария);
    \item коэффициент готовности (надёжности) $\rho_k \in [0, 1]$;
    \item признак ремонта $r_k \in \{0, 1\}$;
    \item множество допустимых типов операций (фрезеровка, сборка, сварка) — связь «ресурс–тип»;
    \item текущая накопленная загрузка $L_k$ (мин).
\end{itemize}

Цель планирования — назначить каждую операцию $O_i$ на один допустимый ресурс из числа тех, для которых тип операции входит в множество допустимых, и определить время её старта $t_i$ так, чтобы минимизировать целевую функцию \cite{averch}. В качестве критериев оптимизации используются:

\begin{itemize}
    \item среднее опоздание $\frac{1}{n}\sum_{i=1}^n \max(0, t_i + p_i - d_i)$;
    \item общая длительность расписания (makespan) $C_{\max} = \max_i (t_i + p_i) - \min_i t_i$;
    \item коэффициент вариации загрузки ресурсов $\text{CV} = \sigma / \mu$, где $\mu$ и $\sigma$ — среднее и стандартное отклонение итоговой загрузки ресурсов.
\end{itemize}

Поскольку точное решение задачи FJSS NP-трудно, в системе применяются эвристические и нейросетевые методы.

\subsection{Эвристический алгоритм распределения операций}

Базовым методом построения расписания является комбинированная эвристика, состоящая из двух правил \cite{babich}:
\begin{enumerate}
    \item EDD (Earliest Due Date) — операции упорядочиваются по возрастанию директивного срока $d_i$, так что наиболее срочные заказы обрабатываются в первую очередь.
    \item LWKR (Least Workload with Knowledge of Route) — для каждой операции из упорядоченного списка выбирается ресурс, имеющий минимальную \textit{эффективную загрузку} среди допустимых по типу.
\end{enumerate}

Эффективная загрузка ресурса $R_k$ вычисляется по формуле:

\begin{equation}\label{eq:effload}
    E_k = \frac{L_k}{\rho_k \cdot (1 - 0.5 \cdot r_k)},
\end{equation}

где $L_k$ — уже назначенная ресурсу суммарная длительность (мин), $\rho_k$ — коэффициент готовности, $r_k$ — признак ремонта. При $\rho_k = 0$ принимается $E_k = \infty$, что исключает полностью неработоспособный ресурс.

\subsection{Генерация синтетических данных для обучения}

Для обучения нейросетевых диспетчеров требуется размеченная выборка, в которой каждому состоянию системы соответствует «правильный» ресурс, назначенный экспертной стратегией \cite{generativ}. В качестве такой стратегии выбран описанный выше эвристический алгоритм, поскольку он детерминирован, интерпретируем и даёт приемлемые расписания. Процесс генерации реализован в модуле \texttt{gpss\_simulator.py} и имитирует поведение производственного диспетчера.

Для каждого синтетического сценария случайным образом создаются $m = 5$ ресурсов с характеристиками: $\rho_k$ принимает значения от 0.5 до 1.0, $r_k$ равен 0 или 1 с вероятностью 10\%, набор поддерживаемых типов $T_k$ (от одного до трёх случайных типов). Затем генерируется от 1 до 10 операций со случайными параметрами: тип операции (фрезеровка, сборка или сварка), $p_i$ от 10 до 120 мин, $d_i$ — случайный срок, $w_i$ от 0.5 до 2.0.

Для каждой операции алгоритмом LWKR определяется целевой ресурс $k^*$ и вычисляется вектор признаков фиксированной размерности 36. Структура вектора включает:

\begin{itemize}
    \item 6 признаков операции: one-hot кодировка типа (3 бита), $p_i / 120$, $w_i$, запас времени (slack) / 48;
    \item для каждого из 5 ресурсов по 6 признаков: статус (1/0), текущая загрузка $L_k/240$, совместимость с типом операции (1/0), средняя загрузка, $r_k$, $\rho_k$.
\end{itemize}

Таким образом, каждый пример представляет собой пару $(\mathbf{x} \in \mathbb{R}^{36}, y \in \{0, \dots, 4\})$, где $y$ — индекс выбранного ресурса. Сгенерированный набор сохраняется в файл \texttt{gpss\_dataset.npz} и насчитывает около 27\,000 примеров.

\subsection{Нейросетевые модели диспетчеризации}

В системе реализованы две архитектуры нейросетевых диспетчеров, а также три метода обучения.

\subsubsection{Многослойный перцептрон SimpleDispatcher}

Для конфигурации с фиксированным числом ресурсов ($m = 5$) используется модель прямого распространения \texttt{SimpleDispatcher} \cite{MLP}, архитектура которой показана на рисунке~\ref{SimpleDispatcher:image}.

\begin{figure}[H]
\centering
\includegraphics[width=1\linewidth]{SimpleDispatcher}
\caption{Архитектура нейросети SimpleDispatcher (MLP)}
\label{SimpleDispatcher:image}
\end{figure}

Входной слой из 36 нейронов принимает вектор признаков $\mathbf{x}$. Далее следуют:

\begin{itemize}
    \item полносвязный слой с 64 нейронами и функцией активации ReLU;
    \item пакетная нормализация (BatchNorm1d);
    \item полносвязный слой с 32 нейронами и активацией ReLU;
    \item пакетная нормализация;
    \item выходной полносвязный слой из $m = 5$ нейронов, выдающий логиты $z_k$.
\end{itemize}

Выходное распределение вероятностей получается применением softmax к логитам, после чего учитывается поправка на готовность ресурса (аналогично формуле \ref{eq:effload}). Модель обучается минимизации кросс-энтропии между предсказанным и целевым распределениями.

\subsubsection{Pointer Network для переменного числа ресурсов}

Для поддержки произвольного числа ресурсов разработана модель на основе механизма внимания (Pointer Network), изображённая на рисунке~\ref{pointer:image}. Она принимает два входа: вектор операции $o \in \mathbb{R}^6$ и матрицу ресурсов $R \in \mathbb{R}^{m \times 6}$. Оба входа линейно преобразуются в эмбеддинги размерности $d_{\text{model}}$, после чего многоголовое внимание (Multi-Head Attention) вычисляет контекстный вектор операции относительно всех ресурсов. Контекст объединяется с исходным эмбеддингом операции и пропускается через два полносвязных слоя с ReLU. Выходной слой формирует $m$ логитов. Модель не зависит от порядка ресурсов и естественно масштабируется на любое $m$ \cite{deeplearning, neuralnetspython, intsysandtech}.

\begin{figure}[H]
\centering
\includegraphics[width=1\linewidth]{ArchPointerNet}
\caption{Архитектура диспетчера на основе Pointer Network}
\label{pointer:image}
\end{figure}

Архитектура модели состоит из следующих последовательных компонентов.

\begin{enumerate}
\item Входные данные. Модель принимает два входных тензора: вектор признаков операции $o \in \mathbb{R}^{1 \times 6}$ и матрицу признаков ресурсов $R \in \mathbb{R}^{N \times 6}$, где $N$ — текущее количество ресурсов. Шесть признаков операции включают: one-hot кодировку типа (3 бита), нормализованную длительность (мин/120), приоритет заказа и slack (часы до дедлайна / 48). Каждый из $N$ ресурсов описывается шестью признаками: статус (1/0), текущая загрузка (мин/240), совместимость с типом операции (1/0), средняя загрузка, флаг ремонта (0 или 1) и коэффициент готовности $\rho \in [0,1]$.
\item Кодировщик операции. Полносвязный слой с функцией активации ReLU, преобразующий вектор $o$ в эмбеддинг $e_o \in \mathbb{R}^{1 \times d_{\text{model}}}$, где $d_{\text{model}}$ — размерность пространства эмбеддингов. Этот слой выделяет значимые признаки операции для последующего сравнения с ресурсами.
\item Кодировщик ресурсов. Полносвязный слой с ReLU, применяемый независимо к каждому из $N$ ресурсов и формирующий матрицу эмбеддингов $E_r \in \mathbb{R}^{N \times d_{\text{model}}}$. Раздельное кодирование позволяет извлечь признаки, специфичные для ресурсов, до их взаимодействия с операцией.
\item Блок многоголового внимания (Multi-Head Attention). Эмбеддинги подаются в блок внимания, где запрос (Query) формируется из эмбеддинга операции: $Q = e_o W^Q$, а ключи (Keys) и значения (Values) — из эмбеддингов ресурсов: $K = E_r W^K$, $V = E_r W^V$, где $W^Q, W^K, W^V$ — обучаемые матрицы весов. Механизм внимания вычисляет коэффициенты значимости каждого ресурса относительно операции по формуле:
    \begin{equation}
        \text{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V,
    \end{equation}

где $d_k = d_{\text{model}} / h$, $h$ — число голов. Многоголовое внимание позволяет одновременно учитывать различные типы взаимосвязей между операцией и ресурсами (совместимость по типу, загрузку, готовность). Результатом является контекстный вектор $c \in \mathbb{R}^{1 \times d_{\text{model}}}$, агрегирующий информацию о всех ресурсах.

\item Объединение контекста и эмбеддинга операции. Контекстный вектор $c$ объединяется с исходным эмбеддингом операции $e_o$ (конкатенацией), образуя расширенный вектор $u = [c; e_o] \in \mathbb{R}^{1 \times 2d_{\text{model}}}$. Это позволяет сохранить как информацию о ресурсах, так и исходные свойства операции.

\item Полносвязный слой 1. Имеет 64 фильтра. Слой с функцией активации ReLU преобразует $u$ в скрытое представление размерности $d_{\text{ff}}$. Выполняет первичную обработку объединённого вектора.

\item Полносвязный слой 2. Имеет 64 фильтра. Второй слой с ReLU дополнительно нелинейно трансформирует признаки, формируя более абстрактное представление для итогового решения.

\item Выходной слой. Полносвязный слой формирует $N$ логитов — по одному для каждого ресурса. К логитам применяется поправка на готовность ресурса, аналогичная эвристической формуле: к логарифму вероятности добавляется слагаемое $\ln(\rho_k \cdot (1 - 0.5 \cdot r_k) + \varepsilon)$, где $\varepsilon = 10^{-6}$ для численной стабильности. Затем softmax-функция преобразует скорректированные логиты в вероятности назначения операции на каждый ресурс.

\item Принятие решения. Ресурс с максимальной вероятностью выбирается в качестве результата — индекс $k^* = \arg\max_k P_k$.
\end{enumerate}

\subsubsection{Методы обучения нейросетевых диспетчеров}

В системе поддерживаются три парадигмы обучения \cite{sravnenieNS}:

\begin{enumerate}
\item Behavioral Cloning (BC, PointerNet). Модель обучается на наборе примеров $(x^{(j)}, y^{(j)})$, сгенерированных эвристикой, путём минимизации кросс-энтропийной функции потерь:
\begin{equation}
    \mathcal{L}_{\text{BC}} = -\frac{1}{N}\sum_{j=1}^{N} \log P_{\text{модели}}(y^{(j)} \mid x^{(j)}).
\end{equation}

После обучения модель способна мгновенно воспроизводить решения «учителя», достигая точности классификации ресурсов более 97\% на валидационной выборке \cite{practicalml}.

\item Self-Labeling (SLIM). Для повышения обобщающей способности применяется процедура саморазметки. После начального обучения BC модель просматривает пул неразмеченных примеров $x$ и отбирает те, для которых максимальная вероятность назначения превышает порог $\theta = 0.95$. Эти примеры вместе с предсказанными метками добавляются в обучающий набор, и модель доучивается. Процесс повторяется каждые $k$ эпох (в экспериментах $k = 30$). Такой подход позволил улучшить показатели планирования без привлечения дополнительной экспертной разметки.

\item Proximal Policy Optimization (PPO). Модель обучается взаимодействуя со средой — симулятором цеха. На каждом шаге агент выбирает ресурс для очередной операции и получает награду $R = -\text{tardiness}$. Цель — максимизировать ожидаемую суммарную награду. Функция потерь PPO включает policy gradient с отношением вероятностей и ограничением на величину изменения политики. Несмотря на теоретическую привлекательность, в проведённых экспериментах PPO показал наихудшие результаты, поскольку в процессе обучения использовались случайные, а не осмысленные признаки состояния.
\end{enumerate}
